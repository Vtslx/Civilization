## 一份基线记录包含什么

1. **范围** —— 代号、Stage 区间，以及属于该版本的模块。
2. **新增能力** —— 该版本为部署带来什么，以行为描述而非宣传口径。
3. **基线合同** —— 该版本必须守住的不变量，每一条都有随仓库发布的测试支撑。
4. **验证命令** —— 如何在本地复现合同结果。
5. **边界** —— 该版本刻意不声称的内容。

## 什么可以对照，什么不可以

- **合同基线**（必须通过的测试）可以直接跨修订对照：跑对应测试，比较通过/失败。
- **测量对照**只在真正跑过并留档的地方存在。本仓库中即 `v0.00.07-helix/experiments/` 下的原生记忆配对 A/B。它测的是同一套部署与自身、只切换一个字段，不是榜单成绩。
- 公共基准数字（LongMemEval、BEAM）来自另一次评测活动，使用各自的 answerer 与 judge，作为背景出现在实验报告中，**不能**与配对 A/B 的百分比横向比较。
- 版本号描述的是**实现线**，不是准确率。更晚的版本不意味着在某个基准上一定更好，它只是另一组经过测试的能力。

## 本目录的公开政策

- 基线记录面向公开发布撰写：不含内部路径、主机、凭据或内部规划文档，只写代码、测试和留档测量能支撑的内容。
- 文档以英文（权威版）与简体中文发布；欢迎以 PR 提交勘误与更多语言。
- 无法被本仓库中的材料支撑的主张一律不写；缺失的测量如实标注为缺失。
