## 1. 要回答的问题

在固定任务上，读取 Civilization 原生（Orion）记忆，相比**同一个模型、同一批题目、仅关闭记忆读取**，答案是否会改变？

这是同一套部署与自身的受控对照，不是 Civilization 与其他模型或其他系统的比较。

## 2. 实验设计

| 项目 | 取值 |
|---|---|
| 两种条件 | `memory_on`（`read_memory = true`）与 `memory_off`（`read_memory = false`） |
| 保持恒定 | 问题文本、选项集合与顺序、task name、会话记忆内容、provider 模型、seed |
| 唯一差异 | `CivilizationRequest.read_memory` |
| 自动写入 | 两种条件均关闭（`write_memory = false`），保证答案键固定 |
| 重复 | 同一 25 题重复 3 轮 → 75 对观测（其中 63 对可回答题） |
| 顺序控制 | 条件顺序按题目序号与轮次交替 |
| 隔离 | 每轮使用全新会话；拒答负控题写入独立的源会话 |
| 评分 | 与合成答案键精确匹配，不使用模型裁判 |

**"开启记忆"具体做了什么。** 当 `read_memory = true` 时，服务在作出决策前从会话存储中检索最匹配的记忆单元并注入普通预测上下文。响应会带上 Orion trace（`retrieved_cell_ids`、`injected_item_count`），因此"记忆是否真的被使用"由 trace 核验，而不是靠答案反推。

**实验材料。** 25 道四选一合成题，覆盖六个维度：事实回忆（5）、偏好回忆（4）、时间排序（4）、相似实体干扰（4）、知识更新（4）、会话隔离与拒答（4）。每轮写入 33 条记忆记录；本次运行配置为最多检索 4 条、最多注入 4 条、每条截断至 512 字符。当前检索是词项重合、记忆系统、重要度、置信度与链接分值构成的词法评分路径——向量检索不在本次部署内，因此不作此声明。

## 3. 结果

### 3.1 总体

| 指标 | memory_on | memory_off | 差异 |
|---|---:|---:|---:|
| 全部题目（含拒答负控） | 75/75（100%） | 29/75（38.7%） | +61.3 个百分点 |
| 可回答题 | 63/63（100%） | 17/63（27.0%） | **+73.0 个百分点** |
| 会话隔离/拒答负控 | 12/12（100%） | 12/12（100%） | 无差异 |
| 出现 API 错误的请求 | 0/75 | 0/75 | 无差异 |
| 目标记忆出现在预测上下文 | 63/63（100%） | 0/63（0%） | 符合设计 |

### 3.2 配对结果

| 配对结果 | 对数 |
|---|---:|
| 两边均答对 | 29 |
| 仅 `memory_on` 答对 | **46** |
| 仅 `memory_off` 答对 | **0** |
| 两边均答错 | 0 |
| 配对总数 | 75 |

配对视角比原始差值更值得信任：开启记忆把 46 个错误答案变成了正确答案，且没有任何一对出现"开启记忆后由对变错"。

### 3.3 按问题维度

| 维度 | 唯一题数 | memory_on 正确 | memory_off 正确 | memory_on 独赢 |
|---|---:|---:|---:|---:|
| 事实回忆 | 5 | 15/15 | 3/15 | 12 |
| 偏好回忆 | 4 | 12/12 | 3/12 | 9 |
| 时间排序 | 4 | 12/12 | 1/12 | 11 |
| 相似实体干扰 | 4 | 12/12 | 4/12 | 8 |
| 知识更新 | 4 | 12/12 | 6/12 | 6 |
| 会话隔离与拒答 | 4 | 12/12 | 12/12 | 0 |

增益最大的地方正是"仅凭题面无法作答"的场景：时间排序、事实回忆、偏好回忆以及相似实体消歧。知识更新增益最小，因为关闭记忆时模型靠猜测已经答对了一半。

### 3.4 延迟（观测值，不是吞吐结论）

| 条件 | 均值 | P50 | P95 |
|---|---:|---:|---:|
| memory_on | 1,846.5 ms | 1,804.8 ms | 2,565.1 ms |
| memory_off | 3,585.8 ms | 3,188.6 ms | 6,745.7 ms |

该延迟是单机、固定选项下穿过本地服务与模型网关的端到端观测；生成长度与模型侧波动占主导，因此不能据此宣称记忆路径提升了吞吐。

## 4. 支撑轨道（背景，协议不同）

同一次评测活动还通过本地适配器跑过公共基准（适配器把基准的记忆客户端桥接到 Orion 记忆接口）。这些轨道**没有**做关闭记忆的配对基线，因此不能用来主张记忆增益，仅作为定位数据。

| 轨道 | 样本 | Top-10 | Top-20 | 接口错误 |
|---|---|---:|---:|---:|
| LongMemEval（两个分层 seed 合并） | 12 题，每类 2 题 | 8/12（66.7%） | 9/12（75.0%） | 0 |
| BEAM 100K | 20 题，每类 2 题，写入 94 条记忆 | 13/20（65.0%） | 15/20（75.0%） | 0 |
| BEAM 500K | 6 题，3 类，写入 398 条记忆 | 5/6（83.3%） | 5/6（83.3%） | 0 |
| BEAM 1M | 6 题，3 类，写入 855 条记忆 | 2/6（33.3%） | 2/6（33.3%） | 0 |

已知弱项作为错误定位信号上报，而不是稳定分数（每格仅 2 题）：LongMemEval 偏好类 0/2；BEAM 1M 时间推理 0/2，且同三类从 500K 的 5/6 降至 1M 的 2/6。长上下文表现需要更多 seed、更多对话索引和每类更多题量，才能判断趋势是否稳定。

另有一条单条件轨道直接使用原生 API（不经过基准 answerer 或 judge）：精确匹配 25/25，21 道可回答题的目标记忆全部进入 Top-4，其中 16/21 排名第一（MRR 0.881），4/4 隔离题无跨会话泄漏，4/4 正确拒答，0 接口错误。

## 5. 有效性限制

1. **25 个唯一问题，不是 75 个。** 三轮重复衡量的是同一批题目的稳定性，并未扩大问题样本。
2. **合成长选项题。** 题目使用合成事实与四个选项；选项措辞本身可能携带线索，关闭记忆时模型也允许猜测。应看配对胜负，而不只看总体差值。
3. **仅覆盖会话范围。** 这里的检索来自同一运行进程的会话存储。进程重启后的持久性、global-store 保存/载入、跨用户共享、并发压力、工作记忆过期、程序性记忆以及从自由文本自动抽取记忆，都不在本次实验范围内。
4. **不是基准对比。** LongMemEval 与 BEAM 使用各自的 answerer 与 judge，本次 A/B 使用固定答案键。合成题集上的高分不能证明在公共基准上更优。
5. **检索行为与部署绑定。** 测得的是一套具体配置（Top-4 词法检索、注入 4 条、每条 512 字符）。换配置就是另一个实验。

## 6. 复现方式

复现脚本是自包含的：它内嵌 25 道题的 fixture，除可访问的服务与 `civilization` SDK 外不需要任何外部文件。

```bash
cd docs/versions/v0.00.07-helix/experiments/scripts

# 完整协议：3 轮、25 题、150 次预测
CIVILIZATION_LOCAL_BASE_URL=http://127.0.0.1:8765 \
  python memory_ab.py --rounds 3 --provider-model <model-name> --output memory_on_vs_off.json

# 冒烟运行：1 轮、前 4 题
python memory_ab.py --rounds 1 --max-cases 4 --output smoke.json
```

脚本在服务未就绪时会拒绝运行；每次运行写入以 run id 命名的新会话，并在结果 JSON 中记录逐题预测、检索排名、注入的单元 id、延迟与错误。

**本次公开所做的验证：** 内嵌脚本已对运行中的服务做过 1 轮 3 题的冒烟运行，结果为开启记忆 3/3 正确、关闭记忆 0/3、0 接口错误，配对结构与预期一致。`data/` 中记录的是本文档顶部列出的完整三轮运行。

## 7. 本实验能说明与不能说明什么

**能说明：** 在这组受控的、单一部署的 25 题合成任务集上，读取 Civilization 原生记忆显著提升了决策正确率（46 对由错转对、0 对由对转错），且记忆服务按设计工作（开启记忆时目标单元均被注入，隔离会话边界无泄漏，无接口错误）。

**不能说明：** 相对于其他记忆系统或模型的普遍优势、长期或跨重启记忆行为、自由对话质量，或吞吐收益。
